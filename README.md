# OpenALEX Collector v7.1

OpenALEX Collector v7.1 は、OpenAlex API を中心に、学術論文の収集、Topic分析、資金分析、引用分析、共同研究・共著ネットワーク分析、著者・機関名寄せ、技術キーワード抽出、読むべき論文のトリアージ、技術系譜、ジャーナル分析、そして AI 分析レポート用プロンプト生成をブラウザ上で行うための単一HTMLツールです。

サーバーは不要です。`OpenALEX_Collector.html` をブラウザで開くだけで利用できます。OpenAI、Anthropic、Google などの外部AI APIはツール本体から呼び出しません。AIを使う場合は、Collectorが生成したプロンプトをユーザーが確認し、外部AIへ手動で貼り付け、返ってきたTSVをCollectorへ貼り戻す設計です。

> **重要（2026年2月の変更）:** OpenAlex API は 2026年2月13日より **APIキーが必須** になりました（従来の `mailto` / polite pool 方式は廃止）。利用前に OpenAlex の **無料アカウント** でキーを取得し、アプリ内の「OpenAlex APIキー」画面で設定してください（→ [クイックスタート](#クイックスタート)）。これは外部AI API（OpenAI / Anthropic など）とは別物で、**AI APIキーは引き続き不要**です。

> すべての論文は、誰かの肩である。

## 概要

**OpenALEX Collector v7** は、OpenAlexの論文メタデータを起点に、研究領域の構造を多面的に把握するための分析ツールです。v6.0で整備した検索、Topic分析、資金分析、引用分析、共同研究・共著ネットワーク、引用ネットワーク、著者・機関名寄せを継承し、v7では技術キーワード抽出、AI注釈、読むべき論文の優先順位付け、技術系譜、AI分析レポート用プロンプト生成を追加しています。

主に次の問いに答えることを目的にしています。

- その研究領域は伸びているのか。
- どのTopicが増えているのか。
- どの論文、著者、機関、ジャーナルが影響力を持つのか。
- 同姓同名の著者や同名・類似名の機関が、ランキングやネットワークを歪めていないか。
- どの機関どうし、どの著者どうしが共同研究・共著しているのか。
- どの著者がどのTopicを担っているのか。
- どの資金源・助成番号が、どのTopic、機関、著者に関係しているのか。
- どの文献が基礎文献、共通基盤、内部引用ハブになっているのか。
- 大量の論文集合から、まず読むべき文献をどう絞るか。
- OpenAlex Topicの抽象的な名称を、技術調査で使いやすい名前にどう言い換えるか。
- 論文タイトルや要約から、技術ポイント候補をどう抽出するか。
- 代表論文どうしの先後関係を、引用・Topic・技術語・共著関係・書誌結合からどう読むか。
- 外部AIに渡す前に、根拠データをどう整理すべきか。
- APIを使わずに、GPT / Claude など外部AIへ安全に渡すプロンプトをどう作るか。

v7のAI支援機能は、Collector内でAI推論を実行するものではありません。Collectorは論文集合から、母集合サマリー、技術キーワード、読むべき論文候補、技術系譜ノード、Topic命名用データ、AI分析レポート用プロンプトを生成します。ユーザーは内容を確認したうえで外部AIへ手動投入し、返ってきたTSVをCollectorへ貼り戻します。貼り戻されたAI注釈は、読むべき論文、技術系譜、Topic表示、総仕上げプロンプト、CSV出力に反映されます。

## v7の設計方針

| 方針 | 内容 |
|---|---|
| OpenAlex中心 | 論文母集団形成、Topic、引用文献、機関、著者、資金情報はOpenAlexを主軸にします。 |
| 単一HTML | サーバー不要。ブラウザだけで動作します。 |
| AI APIなし | Collector本体は外部AI APIを呼び出しません。プロンプト生成とTSV貼り戻しだけを扱います。 |
| 分析者主導 | 自動スコア、自動Topic命名、自動系譜化を最終判断にせず、ユーザーが重み、フィルタ、AI貼り戻し結果を確認して使います。 |
| 根拠データ優先 | 外部AIに渡すプロンプトには、Work ID、年、タイトル、Topic、被引用数、著者、機関、ジャーナル、技術キーワードなどの根拠を含めます。 |
| 説明可能なスコア | 読むべき論文候補はブラックボックス推薦ではなく、Topic急増、年齢補正被引用、橋渡し性、技術語新規性、著者・機関シグナル、資金シグナルを明示して計算します。 |
| 系譜ノードを重視 | 読むべき論文リストには、スコア上位だけでなく、技術系譜に入っている論文も含められます。 |
| Topic表示だけをAI置換 | Topic分析では集計キーをOpenAlex Topicのまま保持し、必要に応じて表示名だけAI命名ラベルへ置換します。 |
| 名寄せを分析基盤に統合 | ランキング、引用、共同研究、Topic×機関、Topic×著者、資金源×機関、資金源×著者、ネットワーク分析に著者・機関名寄せを適用します。 |
| ID優先・表示名はラベル | 著者名・機関名は表示ラベルとして扱い、集計はAuthor ID、ORCID、Institution ID、ROR、名寄せマップのcanonical keyを優先します。 |
| 名寄せの混入防止 | 高速化用キャッシュと、ユーザーが判断した名寄せマップを分離します。保存済みマップを明示的に使う設計です。 |
| OpenAlex APIキー（無料・必須） | OpenAlex API は 2026年2月13日より APIキーが必須です（[クイックスタート](#クイックスタート)参照）。アプリ内「OpenAlex APIキー」画面で無料キーを設定します。外部補完の Crossref REST API・NIH RePORTER API は登録不要。AI APIキー欄はありません（プロンプト生成＋TSV貼り戻し方式）。 |
| CSV再利用 | 取得済みCSVを再読み込みして分析を継続できます。v7ではAI注釈カラム、Topic命名カラム、名寄せ関連カラムもCSVに含めます。 |

## 変更履歴

### v7.1（パフォーマンス修正）

v7.1 は機能はv7と同一で、**大規模データ（数万件）でのフリーズを解消したパフォーマンス修正版**です。

- **「技術キーワード・AI注釈」カードの O(N²) を解消**: 「B. AIプロンプト生成」タブに切り替えたとき、および「C. AI結果貼り戻し」を実行したときに走る概要メモ生成（`renderOverview`）で、論文1件ごとに全件の最小・最大出版年を再計算していました（実質 N×N）。これを1回だけの計算に修正しました。数万件で発生していた数秒〜フリーズ級の待ちが解消します（10,000件で該当処理が約640ms→約5ms）。
- **AI結果貼り戻し後の再描画を軽量化**: 貼り戻しのたびに全カード（Topic分析・技術系譜など）を無条件でフル再描画していたのを、**今開いているカードだけ即時更新し、他のカードは次に開いた時に最新で再描画**する方式へ変更しました（既存の遅延描画の仕組みを利用）。貼り戻しの体感が大きく軽くなります（10,000件で約1,300ms→約250ms）。
- **保存済みCSVのアップロード時のフリーズを解消**: CSV読み込みの過程で、著者・機関の名寄せラベル付与（`applyIdentityLabels`）が **2回実行**されていたうえ、論文1件ごとに著者・機関情報を作り直していました。(1) 二重実行を解消し、(2) 名寄せエンティティをデータセット単位でキャッシュして再利用するようにしました。CSVインポート全体が約半分の時間になります（5,000件で約2,380ms→約1,050ms、20,000件規模ではより顕著）。名寄せ結果は修正前と完全に一致することを確認済みです。
- **大容量CSV（数十〜百MB級）のクラッシュを解消（CSVパーサーのメモリ効率化）**: 旧 `parseCSV` には2つの深刻なメモリ問題がありました。(1) 1文字ずつ文字列を連結（`current += ch`）していたため、巨大ファイルで文字列の再確保が大量発生。(2) 全行を中間配列 `lines[]` にいったん保持してから再パースしていたため、元テキストとほぼ同サイズの配列が二重・三重に積み上がっていました。結果として、**CSVファイルサイズの約5倍**ものメモリを消費し、150MB級ではブラウザのJSヒープ上限（約4GB）を超えて**タブがクラッシュ**していました。新実装では、`substring` でフィールドを切り出し、行を1件ずつオブジェクト化して**巨大な中間配列を残さない**方式に全面的に書き換えました。
  - **効果（実測）**: パース後のメモリ増加が **約1/3.5**（12MB CSVで +46MB → +13MB）、パース速度は **約3.4倍**（同 618ms → 182ms）。これにより、**従来クラッシュしていた150MB級のCSVも読み込めるようになりました**（処理可能なファイルサイズの目安が大幅に拡大）。
  - **副次的なバグ修正**: 旧パーサーは「引用符で囲まれたフィールド内のカンマ」を誤って列の区切りとして分割してしまうバグがありました（例: `"Smith, J."` が2列に割れる）。新パーサーはRFC 4180準拠の引用符処理で正しく扱います。エクスポート→インポートの往復で、カンマ・引用符・JSON埋め込みデータを含む全カラムが元データと完全一致することを確認済みです。
- **CSVアップロード中のインジケーター表示**: 大容量CSVの読み込み中は、スピナー付きのオーバーレイ（「CSVを読み込み中...」）を表示し、処理が完了すると自動的に消えます。重い同期処理でも確実に「処理中」が見えるよう、インジケーターを画面に描画してから読み込みを開始する設計にしています。

> 計算結果・表示内容は v7 と同一で、速度・メモリ効率が改善しています（CSVパーサーの引用符バグ修正のみ、結果がより正確になります）。貼り戻し後にTopic分析や技術系譜カードを開くと、その時点で最新の注釈が反映された状態で描画されます。

## v6.0からv7への主な変更点

v7は、v6.0の機能セットを維持したうえで、論文集合を「読む」「説明する」「外部AIで仕上げる」ための補助機能を追加した版です。

| 分類 | v7での内容 |
|---|---|
| 技術キーワード | タイトル・要約からTF-IDFで技術キーワード候補を抽出します。最大フレーズ語数、最小文字数、最小出現文書数、抽出対象上限、追加ストップワードを調整できます。 |
| AI注釈 | 技術ポイント付与TSV、Topic命名TSV、読むべき論文整理TSVを貼り戻せます。OpenAlex由来データは上書きせず、AI注釈として重ねます。 |
| AIプロンプト生成 | 技術ポイント付与、Topic命名、読むべき論文整理、総仕上げレポート用のプロンプトを生成できます。 |
| 読むべき論文 | Topic急増、年齢補正被引用、橋渡し性、技術語新規性、著者・機関シグナル、資金シグナルから優先度スコアを計算します。 |
| 技術系譜 | 内部引用を最優先し、引用関係がない場合はTopic一致、技術キーワード類似度、共著者・機関の継続性、共通参考文献から親子関係を推定します。 |
| 読むべき論文・技術系譜カード | 読むべき論文と技術系譜を1枚のカードにまとめ、タブで切り替えます。 |
| 系譜ノードの読書候補化 | 技術系譜に入っている論文を、スコア上位から漏れていても読むべき候補に追加できます。 |
| 詳細ポップアップ | 読むべき論文リスト、技術系譜リスト、系譜ノードから詳細ポップアップを開けます。AI注釈、読書分類、ノード説明、スコア構成要素も確認できます。 |
| CSV出力 | 通常論文CSVに加え、読むべき論文CSV、技術系譜CSVを保存できます。 |
| Topic分析へのAI反映 | AI Topic命名をTopic分析に反映するモードを追加しました。集計キーは元Topicのまま、表示名だけ置き換えます。 |
| AI分析レポート | 総仕上げカードで、母集合の概観、伸びているTopic、技術キーワード、技術系譜の手がかりを整理し、文章レポート向けプロンプトを生成します。 |
| 検索UI | コマンドライン検索式モードと標準OpenAlex検索モードを明確に分け、コマンドラインモードでは各行のTI/AB/TA/TX/FT指定を優先します。 |
| 大量取得 | 年別取得モードで、年ごとに取得上限を設定して大規模母集合へ対応します。 |
| 名寄せ | v6.0の著者・機関名寄せ、名寄せ診断、名寄せマップJSON、各分析への適用を継承します。 |

## クイックスタート

### 0. OpenAlex APIキーを設定する（初回のみ・必須）

2026年2月13日より、OpenAlex API の利用には **APIキーが必須** です（無料）。従来の `mailto`（polite pool）方式は廃止されました。

1. [openalex.org](https://openalex.org) で **無料アカウント** を作成します（メールアドレスのみ・約30秒）。
2. ログイン後、[openalex.org/settings/api](https://openalex.org/settings/api)（Settings → API）を開きます。
3. 表示された **API key** をコピーします。
4. 本ツールを開き、左サイドバー上部の **「OpenAlex APIキー」** 画面でキーを貼り付けて **「保存」** をクリックします。**「接続テスト」** でキーの有効性を確認できます。

- キーはお使いの **ブラウザの `localStorage` にのみ保存** され、OpenAlex API 以外には送信されません。共用PCでは使用後に「クリア」してください。
- キー未設定でも1日あたり約100リクエストの **お試し枠** で動作しますが、超過すると `403` 等のエラーになります。
- 無料枠は **1日あたり10万クレジット（約 $1 相当）**：単一論文取得は無制限／リスト・フィルタ検索 10,000回／全文検索 1,000回／全文DL 100回 など（操作種別ごとの目安）。学術研究で上限引き上げが必要な場合は support@openalex.org に相談できます。
  - ここでの **「全文DL」は論文PDF本文のダウンロード** を指します。**本ツールはメタデータのみを取得し、全文DLは一切使いません**。したがって「全文DL 100回/日」の枠に当たることはなく、実際に効くのは検索（約1,000回/日）と一覧取得（約1万回/日）の枠です。通常の調査用途なら無料枠で十分です。
- これは外部AI API（OpenAI / Anthropic / Google など）とは別物です。AI分析はプロンプト生成＋TSV貼り戻し方式のため、**AI APIキーは引き続き不要** です。

### 操作フロー

```bash
# 1. HTMLファイルをブラウザで開く
open OpenALEX_Collector.html

# （初回のみ）左サイドバー上部の「OpenAlex APIキー」画面で無料APIキーを設定 ← 上記「0.」を参照

# 2. コマンドライン検索式、または標準OpenAlex検索を入力
# 例:
# #01  TA=((sulfide OR oxide OR polymer) near5 electrolyte)
# #02  AB=(degradation OR interface)
# T=(#01 AND #02)

# 3. 必要に応じて所属機関フィルタ、著者フィルタ、年範囲、詳細フィルタを指定

# 4. 「検索を実行」をクリック

# 5. 論文データを確認

# 6. 必要に応じて「技術キーワード・AI注釈」で技術キーワードを確認し、AIプロンプトを生成

# 7. 著者・機関名寄せで、同姓同名・同名機関・親機関寄せを確認

# 8. グラフ、引用、共同研究、資金、Topic、ネットワーク、引用ネットワークを描画

# 9. 「読むべき論文・技術系譜」で、文献候補と系譜を確認

# 10. 必要に応じてプロンプトを外部AIへ貼り付け、TSVをCollectorへ貼り戻す

# 11. 最後に「AI分析レポート（総仕上げ）」で概観・系譜プロンプトを生成

# 12. CSV / PNG / Markdown / JSON を保存
```

推奨ブラウザは、Chrome、Edge、Firefox、Safariなどのモダンブラウザです。ローカルHTMLとして動作しますが、Chart.js と vis-network はCDNから読み込むため、グラフやネットワーク機能を使うにはインターネット接続が必要です。

## モジュール詳細

### 画面構成（サイドバー・タブUI）

v7のUIは、左サイドバーのタブ構成です。各機能カードはサイドバーのグループから選び、**1枚ずつ全幅で表示**します。横長のテーブル・ネットワーク図・技術系譜・マトリクスがはみ出さず、画面の横幅を広く使えます。

| サイドバーのグループ | 含まれるカード |
|---|---|
| 取得・データ | 論文検索 / 論文データ / 著者・機関名寄せ |
| 技術キーワード | 技術キーワード・AI注釈 |
| 計量分析 | グラフ / 引用ランキング / Topic分析 / 資金分析 / ジャーナル分析 |
| ネットワーク | 共同研究ネットワーク / ネットワーク図 / 引用ネットワーク |
| 技術の系譜と重要論文 | 読むべき論文・技術系譜 |
| レポート | AI分析レポート |

- 件数・期間などのメトリクスはサイドバー外にあり、**どのタブでも上部に常時表示**されます。
- 検索を実行すると、自動的に「論文データ」タブへ切り替わります。
- 各カードは**表示した時に計算**されるため（遅延描画）、大規模データでも検索直後にフリーズしません。
- 各カード内のサブタブ（グラフ4種、引用6種など）は従来どおりです。
- 画面幅が狭い場合は、サイドバーが上部の横並びメニューに自動で切り替わります。

### 1. 論文検索

論文検索カードでは、OpenAlex APIに対する検索条件と、取得後のCollector内部フィルタを設定します。

#### 検索モード

| モード | 内容 | 使いどころ |
|---|---|---|
| コマンドライン検索式 | `#01`、`#02` のような番号付き行に検索条件を書き、`T=(#01 AND #02) OR #03` で結合します。 | 特許検索・文献検索に近い形で、タイトル、要約、近傍演算、除外条件を明示したい場合。 |
| 標準OpenAlex検索 | 検索語をOpenAlexへ直接渡します。1行1クエリ、複数行でOR検索できます。 | すばやく広く検索したい場合。OpenAlexの検索仕様に寄せたい場合。 |

コマンドライン検索式モードでは、各行に `TI=` / `AB=` / `TA=` / `TX=` / `FT=` のいずれかを明示します。詳細フィルタの「検索範囲」は無効化され、各行のフィールド指定が優先されます。

標準OpenAlex検索モードでは、詳細フィルタの「検索範囲」を使えます。選択肢は、全文、タイトル＋要約、タイトル、要約、fulltext です。

#### コマンドライン検索式

例:

```text
#01  TI=(solid adj3 electrolyte)
#02  AB=((degradation AND capacity) near8 (mechanism OR fade*))
#03  TA=(review)
T=(#01 AND #02) AND NOT #03
```

| 記法 | 意味 |
|---|---|
| `TI=(...)` | タイトルを対象にします。 |
| `AB=(...)` | 要約を対象にします。 |
| `TA=(...)` | タイトル＋要約を対象にします。 |
| `TX=(...)` | OpenAlex総合検索対象を使います。候補取得中心です。 |
| `FT=(...)` | OpenAlex fulltext索引を使います。候補取得中心です。 |
| `AND` | 両方を含みます。 |
| `OR` | いずれかを含みます。 |
| `NOT` | 除外します。 |
| `nearN` | 順不同でN語以内に現れることを要求します。 |
| `adjN` | 左の語が右の語より前、N語以内に現れることを要求します。 |
| `*` | 任意長のワイルドカードです。例: `cathod*` |
| `?` | 1文字ワイルドカードです。例: `wom?n` |

通常の `TI` / `AB` / `TA` キーワード検索、Boolean、ワイルドカードでは、OpenAlex候補をそのまま採用します。Collector内部で厳密な距離判定を行うのは、原則として `TI` / `AB` / `TA` に `nearN` / `adjN` を使った場合です。`TX` / `FT` はOpenAlex索引による候補取得中心であり、Collector内部での厳密なnear/adj検証やスニペット表示は行いません。

#### 所属機関フィルタ

所属機関フィルタは、検索キーワードとAND検索されます。セミコロン区切りで複数機関を指定するとOR条件になります。

```text
The University of Texas at Austin; Meijo University
https://openalex.org/I136199984
I136199984
```

機関名だけでなく、OpenAlex Institution IDも指定できます。取得後の分析では、機関名寄せによりInstitution ID、ROR、lineage、名寄せマップを使って集計できます。

#### 著者フィルタ

著者フィルタは、検索キーワード・機関フィルタとAND検索されます。セミコロン区切りで複数著者を指定すると、すべての著者を含む論文を抽出します。

```text
Akira Yoshino; John Goodenough
https://openalex.org/A123456789
A123456789
```

著者名だけでなく、OpenAlex Author IDも指定できます。取得後の分析では、Author ID、ORCID、名寄せマップを使って著者単位の集計を行います。

#### 年範囲と年別取得

開始年・終了年で出版年を制限できます。年別取得をONにすると、年ごとにOpenAlex検索を実行し、年あたりの取得上限を設定できます。大規模な研究領域で10,000件を超える可能性がある場合に使います。

年別取得は「必ず10,000件を取得する」機能ではありません。検索条件に該当する実件数、年範囲、論文種別、要約あり、英語のみ、OAのみ、最小引用数などの条件によって、実際の取得件数は少なくなります。

#### 詳細フィルタ

| フィルタ | 内容 |
|---|---|
| 論文種別 | Article、Review、Book Chapter、Book、Dataset、Preprint、Dissertation、Editorial、Letter、Reportを複数選択できます。 |
| 検索範囲 | 標準OpenAlex検索時のみ有効です。コマンドライン検索式では各行のフィールド指定が優先されます。 |
| ソート順 | 関連度順、引用数順、新しい順、古い順を選べます。 |
| 最小引用数 | 被引用数が指定値以上の論文だけに絞ります。 |
| OAのみ | オープンアクセス論文だけに絞ります。 |
| 要約ありのみ | `has_abstract:true` を使って要約を持つ論文に絞ります。 |
| 英語論文のみ | `language:en` に加え、タイトルにCJK等が含まれるものを除外します。 |

### 2. 論文データ

論文データカードでは、取得した論文を一覧表示します。タイトル、年、著者、機関、ジャーナル、被引用数、Topic、DOI、Collector内部一致情報などを確認できます。

主な機能は次の通りです。

| 機能 | 内容 |
|---|---|
| ページング | 大量データでも表を分割して表示します。 |
| ソート | 年、被引用数、タイトルなどの列で並び替えます。 |
| 詳細表示 | 行の詳細ボタンから、論文メタデータ、著者、機関、Topic、資金、引用文献、AI注釈を確認できます。 |
| CSVダウンロード | 現在の論文集合をCSV保存します。AI注釈や名寄せ用IDも含めます。 |
| CSVアップロード | 保存済みCSVを読み込み、検索なしで分析を再開できます。 |

CSV再読込では、v7のAI注釈カラム、Topic命名カラム、著者・機関IDカラム、資金情報カラムがあれば復元します。古いCSVでIDカラムがない場合は、名前のみのキーとして扱われます。

### 3. 技術キーワード・AI注釈

技術キーワード・AI注釈カードは、論文データカードの直下に配置されています。検索結果を確認した直後に、技術キーワード、AIプロンプト、AI結果貼り戻しを扱えるようにするためです。

このカードは3つのタブで構成されます。

| タブ | 内容 |
|---|---|
| A. 技術キーワード | タイトル・要約からTF-IDFで技術キーワード候補を抽出します。 |
| B. AIプロンプト生成 | 技術ポイント付与TSV、Topic命名TSV、読むべき論文整理TSVを外部AIへ依頼するためのプロンプトを生成します。 |
| C. AI結果貼り戻し | 外部AIが返したTSVを取り込み、論文・Topic・読むべき論文へAI注釈として反映します。 |

#### 操作の流れ

```text
1. 技術キーワードを確認
  ↓
2. 目的別プロンプトを生成
  ↓
3. 外部AIへ手動で貼り付け
  ↓
4. AIのTSV出力をCollectorへ貼り戻し
  ↓
5. 読むべき論文、技術系譜、Topic表示、総仕上げプロンプト、CSVへ反映
```

CollectorはAI APIを呼び出しません。プロンプトとTSVをユーザーが確認して扱うため、外部送信されるデータを事前に把握できます。

#### 技術キーワードタブ

技術キーワードタブでは、以下のパラメータを調整できます。

| パラメータ | 内容 |
|---|---|
| 表示キーワード数 | 表示するキーワード候補の件数。 |
| 最大フレーズ語数 | 1語、2語、3語など、何語フレーズまで抽出するか。 |
| 語の最小文字数 | 短すぎる語を除外します。 |
| 最小出現文書数 | 何本以上の論文に出現した語句を残すか。 |
| 抽出対象上限 | TF-IDF計算に使う論文数の上限。 |
| 追加ストップワード | 検索語そのもの、分野内で広すぎる語、一般語を除外できます。 |

#### AIプロンプト生成タブ

生成できるプロンプトは次の3種類です。

| 種別 | 目的 | 想定出力 |
|---|---|---|
| 技術ポイント付与TSV | 論文ごとに短い技術ラベル、短い要約、重要理由を付与する。 | `work_id`付きTSV |
| Topic命名TSV | OpenAlex Topicを、人間が読みやすい技術ラベルへ言い換える。 | `topic_original`付きTSV |
| 読むべき論文整理TSV | 候補論文に読書分類、読む順番、読む理由を付与する。 | `work_id`付きTSV |

技術ポイント付与TSVでは、スコア上位論文だけでなく、現在の技術系譜ノード全件も対象に含めます。これにより、系譜上重要な論文がスコア上位から漏れていても、AI注釈を付けられます。

#### AI結果貼り戻しタブ

貼り戻しフォームは3種類です。

| フォーム | 反映先 |
|---|---|
| 技術ポイント付与TSV | 技術系譜ノード名、読むべき論文の技術ポイント、概観・系譜プロンプト、CSV。 |
| Topic命名TSV | AIカード内のTopic表示、読むべき論文、技術系譜、総仕上げプロンプト、Topic分析の表示名。 |
| 読むべき論文整理TSV | 読むべき論文の分類、読書順、読む理由、CSV。 |

AI貼り戻しは、OpenAlex由来の元データを上書きしません。AI注釈として重ねて表示します。

### 4. 著者・機関名寄せ

著者・機関名寄せカードでは、取得した論文集合に含まれる著者・機関を、ID単位・ROR単位・ユーザー定義の統合単位で扱います。

#### 名寄せの基本方針

| 対象 | 優先キー | 補助情報 |
|---|---|---|
| 著者 | OpenAlex Author ID | ORCID、表示名、共著者、Topic、所属機関 |
| 機関 | OpenAlex Institution ID | ROR、lineage、国、機関タイプ、共同研究先、Topic |
| IDがない著者 | `name:` キー | 表示名のみのため、同姓同名混入に注意 |
| IDがない機関 | `name:` キー | 表記揺れ・同名機関混入に注意 |
| ユーザー統合 | `group:` キー | 企業グループ、大学本体＋病院、研究所群などを分析目的で統合 |

v7では、名寄せはランキング、引用、共同研究、Topic×機関、Topic×著者、資金源×機関、資金源×著者、ネットワーク分析に適用されます。

#### GUI名寄せ

名寄せワークベンチでは、対象を「著者」または「機関」に切り替え、一覧を更新して確認します。各行の「詳細・名寄せ」からポップアップを開き、論文、共著者/共同研究先、Topic、同じ名前の候補を確認しながら統合できます。

主な操作は次の通りです。

| 操作 | 内容 |
|---|---|
| 候補をここへ統合 | 表示中のキーへ別キーを統合します。 |
| ここを候補へ統合 | 表示中のキーを別キーへ統合します。 |
| 一括統合 | チェックした複数キーを、表示順で最初のキーへ統合します。 |
| 分離 | クリックで作成した統合ルールを削除し、元のID/ROR/nameキーへ戻します。 |
| JSON出力 | 名寄せマップを保存します。 |
| JSON読込 | 保存済み名寄せマップを再適用します。 |

#### 機関集計単位

| モード | 内容 |
|---|---|
| 個別ID | OpenAlex Institution ID / RORを個別機関として扱います。 |
| 親機関寄せ | lineageを使い、親機関単位へ寄せます。ただし親IDの名称が取得できない場合は個別機関を維持します。 |
| 統合マップ優先 | ユーザーが作成した名寄せマップを優先します。企業グループや任意の分析単位に向きます。 |

#### 名寄せ診断

検索またはCSV読込後、以下を確認できます。

| 診断 | 内容 |
|---|---|
| 著者IDカバレッジ | 著者出現のうち、OpenAlex Author IDまたはORCIDを持つ割合。 |
| 著者 名前のみ（IDなし） | OpenAlex Author ID・ORCIDがなく、名前だけになっている著者出現数。 |
| 同じ名前・複数著者キー候補 | 同じ表示名だが複数キーに分かれている候補。 |
| 機関ID/RORカバレッジ | 機関出現のうち、OpenAlex Institution IDまたはRORを持つ割合。 |
| RORあり所属 | RORを持つ所属出現数。 |
| 同じ名前・複数機関キー候補 | 同じ表示名だが複数キーに分かれている候補。 |

### 6. 引用ランキング

引用ランキングカードでは、論文・著者・機関・ジャーナルの影響力を引用数から確認します。

| 分析 | 内容 |
|---|---|
| 高被引用論文 | 被引用数の多い論文を表示します。 |
| 著者引用ランキング | 著者単位で合計引用数、平均引用数、論文件数などを確認します。 |
| 機関引用ランキング | 機関単位で合計引用数、平均引用数、論文件数などを確認します。 |
| ジャーナルランキング | 掲載先ジャーナル・会議・出版元ごとの件数と引用状況を確認します。 |
| 量×質散布図 | 論文件数と平均引用数の関係を可視化します。 |
| h-indexランキング | 著者・機関のh-index的な指標を表示します。 |

著者・機関のランキングには名寄せ結果が反映されます。クリック可能なチャートや表では、対象論文の詳細ポップアップを開けます。

### 7. 共同研究ネットワーク（機関集計）

共同研究ネットワークカードでは、機関間の共著関係を分析します。

| 分析 | 内容 |
|---|---|
| 機関ペア | 同一論文に現れる機関ペアを集計します。 |
| Egoネットワーク | 指定機関と共同研究している相手機関を表示します。 |
| 共同先の広がり | 各機関が何種類の相手機関と共同しているかを確認します。 |
| ペア時系列 | 特定ペアの年次推移を確認します。 |
| 共同研究マトリクス | 機関×機関の共著件数を行列で確認します。 |

このカードは、研究コミュニティ、企業・大学連携、国際共同研究、研究拠点の広がりを確認するのに向いています。

### 8. 資金分析（Funding Intelligence）

Funding Intelligence では、OpenAlexの助成情報に加え、必要に応じてCrossref REST APIやNIH RePORTER APIから補完した資金情報を使って分析します。

| 分析 | 内容 |
|---|---|
| 資金源ランキング | funder単位で論文件数、引用数、関連Topicを確認します。 |
| 資金源×年 | 資金源ごとの年次推移を確認します。 |
| 助成番号ランキング | award number単位で出現数を確認します。 |
| 資金源×機関 | どの資金源がどの機関と結びついているかを確認します。 |
| 資金源×著者 | どの資金源がどの著者と結びついているかを確認します。 |
| マトリクス出力 | 資金源×機関、資金源×著者などをCSV保存できます。 |
| 外部補完 | DOI等をもとにCrossref / NIH RePORTERから資金情報を補います。 |

資金情報は論文メタデータの充実度に依存します。資金源が空欄の論文が多い領域では、ランキングやマトリクスは過小評価になり得ます。

### 9. ジャーナル分析（Journal Intelligence）

論文の掲載先（OpenAlex の `primary_location.source`）を単位に、ジャーナルのランキングと、著者×ジャーナル・機関×ジャーナルのクロス集計を行います。ジャーナルの同定キーは **source ID &gt; ISSN-L &gt; 表示名** の優先順で、表記ゆれを吸収します（著者・機関は「著者・機関名寄せ」の設定を引き継ぎます）。

| タブ | 内容 |
|---|---|
| A. ジャーナルランキング | ジャーナル単位の表（論文数／合計被引用／平均被引用／h-index／OA率／年範囲）と上位の棒グラフ。**並び順は「論文数」と「合計被引用数」で切替**できます。 |
| B. 著者 × ジャーナル | 行＝著者（名寄せ後）、列＝ジャーナルのヒートマップ。どの著者がどの雑誌に出しているかを把握します。 |
| C. 機関 × ジャーナル | 行＝機関（名寄せ後・機関集計モードを継承）、列＝ジャーナルのヒートマップ。 |

- **指標の切替**: 画面上部の「指標」で、ランキングの並び順とB/Cヒートマップのセル値を「論文数」「合計被引用数」の間で切り替えます。
- **種別フィルタ**: OpenAlex の source には学術誌のほか会議録・プレプリント（arXiv等）・リポジトリも含まれます。既定は「学術誌（journal）のみ」で、「すべて」「会議録」「リポジトリ／プレプリント」等に切替可能です。
- **クリック導線**: ランキングの行や、ヒートマップのセル・行見出しをクリックすると、該当論文や著者・機関・ジャーナルの詳細を表示します。
- **エクスポート**: ランキングCSV（全ジャーナル）、著者×ジャーナル／機関×ジャーナルのマトリクスCSV（全件）、ランキング棒グラフのPNGを保存できます。
- h-index はこのコレクション内の被引用のみで計算した参考値です（母集合が小さいと過小評価）。OA率は `open_access.is_oa` ベースです。
- 旧バージョンで取得したCSVを再読込した場合、source ID等が無いため表示名で集計され、種別フィルタは「すべて」での利用を推奨します。

### 10. Topic分析（Topic Intelligence）

#### AI Topic命名の反映

この設計により、元データとの照合可能性を保ちながら、レポートや人間の議論では読みやすいTopic名を使えます。

### 13. 読むべき論文・技術系譜

読むべき論文・技術系譜カードは、文献トリアージと技術系譜を1枚にまとめたカードです。タブで `A. 読むべき論文` と `B. 技術系譜` を切り替えます。

#### A. 読むべき論文

読むべき論文タブでは、以下の6要素から説明可能なスコアを計算し、優先して読むべき論文候補を表示します。

| スコア要素 | 意味 |
|---|---|
| Topic急増 | 直近で伸びているTopicに属する論文を評価します。 |
| 年齢補正被引用 | 出版年を考慮し、古い論文だけが有利になりすぎないように引用数を評価します。 |
| 橋渡し性 | 著者数、機関数、Topic、参考文献数などから、領域間をつなぐ可能性を評価します。 |
| 技術語新規性 | TF-IDF技術キーワードに基づき、技術的に特徴のある論文を評価します。 |
| 著者・機関シグナル | 主要著者・主要機関との関係を評価します。 |
| 資金シグナル | 資金情報を持つ論文を評価します。 |

各重みは画面上で調整できます。候補論文数は、スコア上位として何件表示するかを指定します。

`技術系譜ノードも含める` をONにすると、スコア上位から漏れていても、技術系譜に入っている論文を読むべき候補へ追加します。これにより、基礎ノード、分岐ノード、合流ノード、最近の枝葉など、系譜上重要な論文を読み落としにくくなります。

読むべき論文リストでは、各行の詳細ボタンからポップアップを開けます。ポップアップでは、論文メタデータ、AI技術ポイント、短い要約、重要理由、読書分類、読書順、読む理由、スコア構成要素、技術キーワード、Topic、著者、機関、ジャーナルを確認できます。

#### B. 技術系譜

技術系譜タブでは、代表論文ノードを左から右へ伸びるツリー/DAGとして表示します。横位置は年代（古い＝左、新しい＝右）に対応し、各年代の列の中で縦に詰めて配置します。これにより初期から近年まで横方向に広がり、図が極端な縦長になりません。エッジは原則として `先行論文 → 後続論文` です。

親子関係は次の優先順で推定します。

1. コレクション内の直接引用
2. Topic一致
3. 技術キーワードJaccard類似度
4. 共著者・機関の重なり
5. 共通参考文献による書誌結合

直接引用がある場合はそれを最優先します。直接引用がない場合に限り、Topic、技術語、著者・機関、書誌結合から過去の論文の中で最も近い親候補を1つ選びます。最小関係スコアに満たない弱い関係しか持たないノードも、孤立させずに最も近い先行論文へ点線（弱い関連）で接続します。

表示ノードは、被引用数の多い初期論文だけに偏らないよう、年範囲を年代ブロックに分け、各年代の高スコア論文を確保したうえで選びます。これにより、起点・初期文献から近年のフロントまで、系譜が途切れずに表示されます。

| パラメータ | 内容 |
|---|---|
| 表示ノード数 | 系譜に表示する論文ノード数。 |
| 最小スコア | 読むべき論文スコアが指定値未満のノードを除外します。 |
| 最小関係スコア | この値未満の推定エッジは「弱い関連」として点線・淡色で表示します（孤立ノードを系譜につなぐ補助エッジ）。値を上げると明確な関係の実線エッジが減り、補助の点線エッジが増えます。 |
| 起点候補上限 | 系譜の起点候補として扱うノード数を制限します。 |
| 起点引用重み | 起点候補で被引用数をどれだけ重視するか。 |
| 開始年・終了年 | 系譜表示の年範囲を制限します。 |
| Topicフィルタ | 特定Topicやキーワードに関係する系譜だけを表示します。 |

ノードをクリックすると論文詳細ポップアップを開きます。エッジをクリックすると、その関係が直接引用なのか、Topic一致なのか、技術キーワード類似なのか、共著・機関継続なのか、書誌結合なのか、あるいは系譜をつなぐための弱い関連（点線）なのかを確認できます。

技術系譜リストにも詳細ボタンがあり、各ノードのノード説明、AI/読書注釈、親ノード、関係理由を表形式で確認できます。系譜はCSV保存でき、「PNGダウンロード」で系譜図を画像として保存できます。

### 14. AI分析レポート（総仕上げ）

AI分析レポートカードは、ページ下部に配置された総仕上げ用カードです。ここでは、読むべき論文整理やTopic命名そのものではなく、母集合の概観と技術系譜を文章として読み解くためのプロンプトを作ります。

主な出力は次の2つです。

| 出力 | 内容 |
|---|---|
| 領域概略メモ | Collector内の集計値だけで、論文件数、期間、合計被引用数、主要Topic、伸びているTopic、技術キーワード、技術系譜の手がかりを短く整理します。 |
| 概観・系譜プロンプト | 外部AIへ貼り付けるための、文章レポート向けプロンプトを生成します。 |

概観・系譜プロンプトでは、以下のような構成を外部AIに求めます。

1. エグゼクティブサマリ
2. 母集合の読み取り
3. 技術系譜の読み取り
4. 主要技術ポイントとTopicの関係
5. 主要著者、機関、ジャーナル、資金シグナル
6. 読むべき論文ガイド
7. データセットの限界
8. 次に確認すべき観点

出力は `Layer 1: 事実`、`Layer 2: 解釈`、`Layer 3: 洞察`、`Layer 4: 提言` に分けるよう指示します。ただし、Layer 4は強い事業提言ではなく、次に確認すべき観点、追加調査の方向、読み進め方に限定します。

## AI支援機能の考え方

v7のAI支援は、次の3層に分かれます。

| 層 | Collectorが行うこと | 外部AIが行うこと |
|---|---|---|
| 事前整理 | 技術キーワード抽出、読むべき論文スコア、技術系譜、Topic集計、プロンプト生成。 | なし。 |
| 外部AI処理 | プロンプトをユーザーがコピーできる形で出力。 | 技術ポイント付与、Topic命名、読むべき論文整理、文章レポート作成。 |
| 貼り戻し・反映 | TSVを取り込み、論文・Topic・系譜・CSVへ反映。 | なし。 |

この設計には次の利点があります。

- AI APIキーをCollectorへ入力しなくてよい。
- 自動外部送信が発生しない。
- どのデータをAIへ渡すかをユーザーが確認できる。
- AIの出力をTSVとして構造化し、Work IDやTopic名で照合できる。
- AI注釈は元データを上書きせず、後からクリアできる。
- CSVに保存すれば、AI注釈を後日再利用できる。

## TF-IDF技術キーワード抽出

技術キーワード抽出では、タイトルと要約から1〜N語のフレーズを抽出し、TF-IDFで重み付けします。

```text
TF-IDF = TF × (log((文書数 + 1) / (出現文書数 + 1)) + 1)
```

| 要素 | 内容 |
|---|---|
| TF | 対象フレーズの出現頻度。 |
| DF | 対象フレーズが出現する文書数。 |
| IDF | 多くの論文に出すぎる一般語の重みを下げる係数。 |
| ストップワード | 冠詞、前置詞、接続詞、代名詞、助動詞、論文メタ語、研究一般語、汎用形容詞、単位表現などを除外します。 |
| 追加ストップワード | ユーザーが指定した語句を除外します。 |

技術キーワードは、読むべき論文スコア、技術系譜ノードラベル、AIプロンプト、レポート作成の材料として使われます。

---

## 読むべき論文スコアの定義

読むべき論文スコアは、複数のシグナルを0〜1に正規化し、重み付き平均したうえで0〜100点に変換します。

```text
score = 100 × Σ(weight_i × component_i) / Σ(weight_i)
```

既定の重みは次の通りです。

| 要素 | 既定重み | 内容 |
|---|---:|---|
| Topic急増 | 0.25 | 伸びているTopicに属する論文を評価。 |
| 年齢補正被引用 | 0.20 | 出版年を考慮した引用影響度。 |
| 橋渡し性 | 0.20 | 著者数、機関数、Topic、参考文献数などから領域横断性を評価。 |
| 技術語新規性 | 0.15 | TF-IDF技術キーワードに基づく特徴度。 |
| 著者・機関シグナル | 0.10 | 主要著者・主要機関との関係。 |
| 資金シグナル | 0.10 | 資金情報・助成情報の有無。 |

重みは目的に応じて調整してください。

| 調査目的 | 推奨調整 |
|---|---|
| 最近の急増テーマを追いたい | Topic急増、技術語新規性を上げます。 |
| 基礎文献・古典的文献を押さえたい | 年齢補正被引用を上げます。 |
| 分野横断・橋渡し論文を探したい | 橋渡し性を上げます。 |
| 主要プレイヤーの動向を重視したい | 著者・機関シグナルを上げます。 |
| 政策・資金の関心を重視したい | 資金シグナルを上げます。 |
| ノイズが多い | 候補論文数を減らし、ストップワードを追加します。 |

---

## 技術系譜の定義

技術系譜は、論文集合から代表ノードを選び、先行論文から後続論文へ向かう関係を推定したものです。厳密な歴史記述ではなく、文献集合内の引用・Topic・技術語・著者/機関・参考文献の関係から、分析者が読むための仮説的マップを作る機能です。

| 構成要素 | 内容 |
|---|---|
| ノード | 代表論文。ラベルはAI技術ポイント、TF-IDF技術語、またはタイトル短縮から作ります。 |
| エッジ | 先行論文から後続論文への関係。直接引用を最優先します。 |
| 起点候補 | 古く、被引用数や内部引用が高く、系譜の根になりやすい論文。 |
| 枝分かれ | Topicや技術キーワードが異なる方向へ展開する部分。 |
| 合流 | 複数のTopic、技術語、共通参考文献を介してつながる部分。 |
| 最近のフロント | 近年の高スコア論文、急増Topicに属する論文。 |

技術系譜は、表示ノード数や最小関係スコアを調整しながら読みます。ノードやエッジが多すぎる場合は、Topicフィルタ、年範囲、最小スコア、最小関係スコアを使って絞り込んでください。

## AIプロンプトの設計

v7では、用途に応じて複数のプロンプトを生成します。

| プロンプト | 目的 | 出力 |
|---|---|---|
| 技術ポイント付与TSV | 論文ごとに技術ラベル、短い要約、重要理由を付ける。 | TSV |
| Topic命名TSV | OpenAlex Topicを人間が読みやすい技術ラベルへ言い換える。 | TSV |
| 読むべき論文整理TSV | 候補論文を分類し、読む順番と読む理由を付ける。 | TSV |
| 概観・系譜プロンプト | 領域全体を文章レポートとして読み解く。 | Markdown等の文章 |

プロンプトには、以下の情報を可能な範囲で含めます。

- 論文件数、年範囲、合計被引用数
- 主要Topic、伸びているTopic
- 技術キーワード候補
- 読むべき論文候補
- 技術系譜ノード
- Work ID、DOI、年、タイトル、ジャーナル、被引用数
- 著者、機関、資金源
- AI貼り戻し済みの技術ポイントやTopic命名

外部AIへの指示では、次の制約を入れます。

- 根拠がない市場予測や実用化状況を書かない。
- 重要な主張にはWork ID、年、タイトルを添える。
- Collectorが渡したデータに基づき、推測は推測として書く。
- TSV出力では指定列を守る。
- OpenAlex由来TopicとAI命名ラベルを混同しない。

なお、`Layer 1: 事実 / Layer 2: 解釈 / Layer 3: 洞察 / Layer 4: 提言` の4層モデルは、概観・系譜プロンプト（総仕上げ）でのみ使います。技術ポイント付与TSV・Topic命名TSV・読むべき論文整理TSVの各プロンプトでは4層モデルを使わず、各項目を簡潔な記述として出力させます（各項目に層ラベルや統計値を混ぜません）。

## AI結果貼り戻しTSV

### 技術ポイント付与TSV

```text
work_id	technical_point	short_summary	importance_reason
```

| カラム | 内容 |
|---|---|
| `work_id` | OpenAlex Work ID。Collector内の論文と照合するキー。 |
| `technical_point` | ノードや表で使いやすい短い技術ラベル。 |
| `short_summary` | 論文の短い説明。 |
| `importance_reason` | なぜ重要、またはなぜ読むべきか。 |

反映先は、読むべき論文リスト、技術系譜ノード、総仕上げプロンプト、CSV出力です。

### Topic命名TSV

```text
topic_original	technology_label	short_definition	representative_keywords	representative_work_ids
```

| カラム | 内容 |
|---|---|
| `topic_original` | OpenAlex Topicの元名称。Collector内のTopicと照合するキー。 |
| `technology_label` | 技術調査の見出しに使える、簡潔で具体的な技術名（名詞句）。件数・被引用数・年・work_idなどの統計値や「本流」等の主観評価は含めません。 |
| `short_definition` | その技術名がカバーする研究対象・手法の範囲を示す、1〜2文の中立的な定義（分析文や統計値ではありません）。 |
| `representative_keywords` | 代表キーワード。 |
| `representative_work_ids` | 代表論文のWork ID。 |

反映先は、AIカード内のTopic表示、読むべき論文、技術系譜、総仕上げプロンプト、Topic分析の表示名です。集計キーは元のOpenAlex Topicのままです。

### 読むべき論文整理TSV

```text
work_id	must_read_category	reading_order	must_read_reason	technical_point	short_summary
```

| カラム | 内容 |
|---|---|
| `work_id` | OpenAlex Work ID。 |
| `must_read_category` | 例: foundation、bridge paper、rising topic、recent must-readなど。 |
| `reading_order` | 推奨読書順。 |
| `must_read_reason` | なぜ読むべきか。 |
| `technical_point` | 任意。技術ポイント付与TSVと同様に反映できます。 |
| `short_summary` | 任意。短い要約として反映できます。 |

現在の論文集合に存在しない `work_id` はスキップされます。取り込み後、反映件数とスキップ件数が表示されます。

## Topicスコアの定義

Topic分析では、主に以下の指標を使います。

| 指標 | 内容 |
|---|---|
| 件数 | 該当Topicを持つ論文件数。 |
| 平均被引用数 | 該当Topicの論文の平均被引用数。 |
| 期間 | 最初の出版年から最後の出版年。 |
| 直近件数 | 直近3年の論文件数。 |
| 直前件数 | 直近3年の前の3年の論文件数。 |
| 増分 | 直近件数 − 直前件数。 |
| 新興Topicスコア | 直近件数、増分、平均被引用数などを組み合わせた簡易スコア。 |

新興Topicスコアは、研究領域の「伸び」を見るための便宜的指標です。件数の少ないTopicでは振れが大きくなります。

## 検索構文

### 検索モード

v7には2つの検索モードがあります。

1. コマンドライン検索式
2. 標準OpenAlex検索

コマンドライン検索式では、複数の検索条件を番号付きで書き、最後にT式で結合します。

```text
#01  TI=(solid adj3 electrolyte)
#02  AB=((degradation AND capacity) near8 (mechanism OR fade*))
#03  TA=(review)
T=(#01 AND #02) AND NOT #03
```

標準OpenAlex検索では、検索語をそのままOpenAlexへ渡します。

```text
"solid state battery"
"sulfide electrolyte"
```

複数行を入力した場合はOR検索として扱います。

### フィールド

| フィールド | 対象 | 備考 |
|---|---|---|
| `TI` | タイトル | near/adjの内部判定対象。 |
| `AB` | 要約 | near/adjの内部判定対象。 |
| `TA` | タイトル＋要約 | near/adjの内部判定対象。 |
| `TX` | OpenAlex総合検索 | 候補取得中心。 |
| `FT` | OpenAlex fulltext索引 | 候補取得中心。 |

### 演算子

| 演算子 | 例 | 意味 |
|---|---|---|
| `AND` | `A AND B` | AとBの両方。 |
| `OR` | `A OR B` | AまたはB。 |
| `NOT` | `A AND NOT B` | Bを除外。 |
| `nearN` | `A near5 B` | AとBが順不同で5語以内。 |
| `adjN` | `A adj3 B` | AがBより前、3語以内。 |
| `*` | `cathod*` | 任意長ワイルドカード。 |
| `?` | `wom?n` | 1文字ワイルドカード。 |

## ユースケース別ガイド

### 大量の論文集合から読む順番を作りたい

1. 年別取得をONにして、母集合を広めに取得します。
2. 論文種別、年範囲、要約あり、英語のみなどでノイズを調整します。
3. 技術キーワード・AI注釈カードで、検索語そのものや一般語を追加ストップワードに入れます。
4. 読むべき論文タブで重みを調整します。
5. 技術系譜ノードも含める設定をONにします。
6. 読むべき論文CSVを保存します。
7. 必要に応じて読むべき論文整理TSVプロンプトを外部AIへ渡し、分類と読書順を貼り戻します。

### Topic名が抽象的で読みにくい

1. Topic分析で主要Topicを確認します。
2. 技術キーワード・AI注釈カードでTopic命名TSVプロンプトを生成します。
3. 外部AIから返ってきたTSVをTopic命名フォームへ貼り戻します。
4. Topic分析の `AIのTopic命名をTopic分析に反映する` をONにします。
5. Topicランキング、Topic×年、Topic×機関、Topic×著者、Topic×資金源を読み直します。

### 技術系譜をレポート化したい

1. 読むべき論文スコアを再計算します。
2. 技術系譜タブで表示ノード数、最小関係スコア、起点候補上限、年範囲、Topicフィルタを調整します。
3. ノードとエッジの詳細をポップアップで確認します。
4. 技術系譜CSVを保存します。
5. AI分析レポート（総仕上げ）で概観・系譜プロンプトを生成します。
6. 外部AIの出力で、各主張にWork ID、年、タイトルが添えられているか確認します。

### 同姓同名の著者が多い分野を分析したい

1. 検索後、著者・機関名寄せを開きます。
2. 著者IDカバレッジと同じ名前・複数著者キー候補を確認します。
3. 同一人物なら統合し、別人なら分離したままにします。
4. 名寄せマップをJSON保存します。
5. 著者ランキング、著者×Topic、著者ネットワークを再描画します。

### 企業グループ単位で機関分析したい

1. 機関名寄せを開きます。
2. 関係会社、研究所、子会社などを確認します。
3. 分析目的に応じて `group:company` のような統合単位へ寄せます。
4. 共同研究、Topic×機関、資金源×機関、機関ネットワークを再描画します。
5. 名寄せマップをJSON保存し、次回分析で再利用します。

### 検索式の母集合を確認したい

1. コマンドライン検索式で構文チェック / OpenAlex候補式プレビューを実行します。
2. Collector候補件数、内部一致件数、除外件数を確認します。
3. `nearN` / `adjN` を使っている場合は、内部一致スニペットを確認します。
4. 除外が多すぎる場合は、近傍距離、近傍グループ最大幅、OR分割上限を調整します。

## 外部APIとデータ取得の考え方

v7は、OpenAlexを母集合形成と基本メタデータ取得の中心に置きます。外部APIは、分析を補強するために限定的に使います。

| API / ライブラリ | 用途 | 備考 |
|---|---|---|
| OpenAlex API | 論文、著者、機関、Topic、引用文献、資金メタデータの取得。 | 検索・分析の基盤です。**2026年2月13日よりAPIキーが必須（無料）** — アプリ内「OpenAlex APIキー」画面で設定（[クイックスタート](#クイックスタート)）。キーは `api_key` パラメータで送信。大量取得時は年別取得を使い、不要な再検索を避けてください。 |
| Crossref REST API | DOIを手がかりにした資金情報の補完。 | すべての論文で資金情報が得られるわけではありません。 |
| NIH RePORTER API | NIH関連の助成情報補完。 | NIH系の研究領域で有効です。 |
| Chart.js | グラフ描画。 | CDNから読み込みます。 |
| vis-network | ネットワーク図と技術系譜図の描画。 | CDNから読み込みます。 |
| 外部AIサービス | Collectorが生成したプロンプトの解釈、TSV生成、文章化。 | Collectorから自動送信しません。ユーザーが手動で利用します。 |

データ取得では、検索条件を広くしすぎると、OpenAlex候補数、取得時間、ブラウザ上の処理負荷が大きくなります。初回は取得上限を小さめにして検索式とノイズを確認し、母集合が妥当になってから年別取得や上限拡大を行う運用を推奨します。

### OpenAlex候補とCollector内部一致

コマンドライン検索式を使う場合、CollectorはOpenAlexから候補集合を取得し、必要に応じて内部判定を行います。

| 段階 | 内容 |
|---|---|
| OpenAlex候補 | OpenAlex APIから返ってきた候補論文。 |
| Collector内部一致 | `nearN` / `adjN` など、Collector側で厳密判定した結果。 |
| Collector内部除外 | OpenAlex候補には含まれたが、内部近傍判定などに合わなかった論文。 |

内部除外が発生するのは、主に `TI` / `AB` / `TA` に近傍演算を使った場合です。通常のキーワード、Boolean、ワイルドカード検索では、原則としてOpenAlex候補を採用します。

### 大量取得時の実務上の目安

| 状況 | 推奨対応 |
|---|---|
| 母集合の妥当性を確認したい | 取得上限を200〜500件程度にして検索式を確認します。 |
| 年次推移を広く見たい | 年範囲を設定し、年別取得をONにします。 |
| 論文数が多すぎてブラウザが重い | 年範囲、論文種別、要約あり、英語のみ、最小引用数で絞ります。 |
| Topic分析やAIプロンプトだけ試したい | まず小さなCSVを作ってワークフローを確認します。 |
| 同じ検索を何度も再実行したくない | 論文CSV、名寄せマップJSON、AI注釈入りCSVを保存します。 |

## 分析結果の読み方

v7は多数の集計・スコア・ネットワークを出しますが、いずれも「調査を始めるための地図」です。最終判断は、詳細ポップアップ、原論文、検索条件、名寄せ状態を確認して行います。

| 出力 | 読み方 | 注意点 |
|---|---|---|
| 件数推移 | 研究領域の量的な伸びを見る。 | 検索式変更やOpenAlex収録差の影響を受けます。 |
| Citation ranking | 影響力の大きい論文・著者・機関を見る。 | 古い論文が有利になりやすいです。 |
| Topic ranking | 領域の主題構造を見る。 | OpenAlex Topicは技術調査上の分類と一致しない場合があります。 |
| Emerging Topic | 最近増えている可能性があるTopicを見る。 | 件数が少ないTopicではスコアが不安定です。 |
| Funding Intelligence | 資金源と研究活動の関係を見る。 | 資金メタデータが空欄の論文が多いと過小評価になります。 |
| Collaboration network | 共同研究の構造を見る。 | 多著者・多機関論文がエッジを強くする場合があります。 |
| Reference network | 共通基盤文献や内部引用ハブを見る。 | 参考文献IDの取得状況に依存します。 |
| Must-read score | 読む順番の候補を作る。 | 重み設定によって順位が変わります。 |
| Technology lineage | 技術展開の仮説マップを見る。 | 直接引用がない関係は推定であり、原論文確認が必要です。 |
| AI labels | 人間が読みやすい表示名として使う。 | 元データではなく注釈です。 |

### 詳細ポップアップで確認すべきこと

- そのランキングやノードを構成する論文が何か。
- 著者・機関が適切に名寄せされているか。
- Topic名が調査目的に合っているか。
- 被引用数だけでなく、出版年や論文種別を見たときに妥当か。
- AI注釈が元論文のタイトル・要約と矛盾していないか。
- 技術系譜の親子関係が、直接引用なのか推定なのか。

## AI出力の検証ポイント

外部AIの出力は、Collectorに貼り戻す前後で検証してください。AI出力は便利ですが、論文ID、Topic、技術名、読書順を誤る可能性があります。

| 確認項目 | 見るべき点 |
|---|---|
| Work ID | `work_id` が現在の論文集合に存在するか。 |
| Topic名 | `topic_original` がCollector内のOpenAlex Topicと一致しているか。 |
| TSV列 | 指定列がタブ区切りで出ているか。列名が変わっていないか。 |
| 技術ラベル | 抽象的すぎないか、複数技術を混ぜすぎていないか。 |
| short_summary | タイトル・要約にない内容を断定していないか。 |
| importance_reason | 被引用数、Topic、系譜上の位置など根拠があるか。 |
| reading_order | 基礎→展開→最近のフロントの流れになっているか。 |
| must_read_category | 分類が重複・曖昧になりすぎていないか。 |
| レポート本文 | Work ID、年、タイトルが根拠として添えられているか。 |
| 提言 | 提供データを超えた市場予測や実用化断定になっていないか。 |

貼り戻し後は、読むべき論文リストと技術系譜の詳細ポップアップで、AI注釈がどの論文に付いたかを確認してください。不要な注釈はクリアできます。後で引き継ぐ場合は、AI注釈入りのCSVを保存します。

## パフォーマンス（速度の工夫）

論文数が多い（数千〜数万件規模）と、取得後の集計やネットワーク計算が重くなり、ブラウザが一時的に固まることがあります。v7では、体感速度を保つために次の5つの工夫を入れています。

### A. 遅延描画（必要になった時だけ計算）

検索直後にすべてのカードを一括計算するのをやめ、**各分析カードはサイドバーで開いた時に初めて計算**します。検索が終わるとまずメトリクスと論文表が表示され、資金分析・Topic分析・技術キーワード・読むべき論文/技術系譜・名寄せ診断は、そのタブを開いた時に計算されます。これにより「検索した瞬間に全部計算してフリーズする」状態を避けます。一度計算したカードはキャッシュされ、再表示は即座です。

### B. メモ化（同じ計算を繰り返さない）

- **技術系譜スナップショットの共有**: 読むべき論文スコアと3種のAIプロンプト生成は、内部で技術系譜を組み立てます。以前はこれが1回の更新で約7回も走っていましたが、**1回だけ計算して使い回す**ようにしました（技術系譜の関係推定はノード数の二乗オーダーで重いため効果大）。
- **集計結果のキャッシュ**: TF-IDF技術キーワード・読むべき論文スコア・Topic集計は、（データセット指紋＋パラメータ＋追加ストップワード）をキーにキャッシュします。タブを切り替えただけ、または表示系のパラメータを変えただけの場合は、重い再計算をせずキャッシュを再利用します（AI注釈に依存しないキーなので、貼り戻し後も表示は正しく更新されます）。

### C. アルゴリズム改善（O(N²)の解消）

- **書誌結合**: 以前は全論文ペアを総当たりで比較していました（O(N²)。N=5,000で約1,250万ペア）。これを**逆引きインデックス**（参考文献→その文献を引用している論文リスト）に変更し、**実際に共通参考文献を持つペアだけ**を生成します。総当たり版と結果が一致することを確認済みです。
- **上限ガード**: 共引用は1論文あたりの参照数に、書誌結合は「極端に多くの論文から引用される文献（ハブ文献）」に上限を設けて最悪計算量を抑えます。**この上限により、超大規模なデータではごく一部のペアが集計対象外になる場合があります（近似）。動作を隠さないよう、ここに明記しています。** 通常の数千〜数万件規模ではまず影響しません。

### D. Web Worker（別スレッド計算）

重い参照分析（共引用・書誌結合）の計算を **Web Worker（メインスレッドとは別スレッド）** で実行し、計算中もUI操作が固まらないようにします。

- **堅牢なフォールバック**: ブラウザがWorkerを使えない環境（ローカルファイル `file://` での表示など）では、自動的に**同期実行へフォールバック**します。Workerが応答しない場合のタイムアウト保険もあるためハングしません。Workerが使えない場合でも、C（逆引きインデックス）により十分高速です。

### E. 名寄せ集計の大規模N最適化（数万件対応）

著者・機関の集計（グラフ、引用ランキング、ジャーナル分析など）は、論文ごとに著者・機関エンティティを取り出して名寄せ適用・集計します。数万件規模では、この処理が繰り返し全件を走査して非常に重くなっていました。次の3点で解消しています。

- **データセット指紋計算のO(1)化**: 内部キャッシュの有効性判定で、毎回「全論文IDのソート＋ハッシュ」を計算していたのをやめ、論文配列が変わらない間は結果を使い回します（この判定が多数のループから呼ばれていたため、数万件では実質O(N²)＝数十秒のフリーズ要因でした）。
- **名寄せラベルの再利用**: 表示名の正規化マップを（データセット＋集計モード）単位でキャッシュし、グラフ・引用ランキング・ジャーナル分析で共有します。
- **エンティティ構築の1回化**: 各論文の「名寄せ済み著者・機関」をデータセット単位で一度だけ構築してキャッシュし、各分析はそれを再利用します。名寄せマップや集計モードを変更すると自動的に作り直されます。

これにより、数万件でも「データ取得後の最初の1回」だけ短時間（名寄せエンティティの構築）で済み、**2回目以降のカード表示・タブ切替・指標切替はほぼ瞬時**になります。

### 全体の効果

A（一括計算の廃止）＋B（再計算の排除）＋C（O(N²)の解消）＋D（別スレッド化）＋E（名寄せ集計の最適化）の組み合わせで、数万件規模の母集合でも「検索直後のフリーズ」「カード操作時の固まり」が大きく改善します。それでも重い場合は、各カード内のフィルタ（最小エッジ重み、表示ノード数、対象年、Topicフィルタ、最小出現文書数、ジャーナル分析の行列上限など）で対象を絞ると、さらに軽くなります。なお、ブラウザのメモリやマシン性能にも依存するため、極端に大きな母集合では取得上限を分割する運用も有効です。

## 注意事項

- OpenAlexのメタデータ品質、Topic付与、引用文献、資金情報は分野や時期によってばらつきます。
- 被引用数は取得時点のOpenAlexデータに依存します。
- TopicはOpenAlex側の分類であり、技術調査上の分類と一致しない場合があります。
- AI Topic命名は表示名の補助であり、元Topicを置換するものではありません。
- 技術系譜は、論文集合内のデータから推定した仮説的マップです。実際の技術史を保証するものではありません。
- 読むべき論文スコアは、調査目的に応じて重みを調整してください。
- 外部AIへ貼るプロンプトには論文タイトル、要約、著者、機関などが含まれる場合があります。外部AIサービスの利用規約や組織ポリシーに従ってください。
- ローカルHTMLですが、CDNライブラリや外部APIを使う機能にはインターネット接続が必要です。
- 大規模データでの体感を保つため、各分析カード（資金、Topic、技術キーワード・AI注釈、読むべき論文・技術系譜、名寄せ診断）はスクロールして表示した時に計算します。検索直後はメトリクスと論文表が先に表示され、巨大な一括計算によるフリーズを避けます。
- 共引用・書誌結合の重い計算はWeb Workerで別スレッド実行し、利用できない環境（一部のローカルファイル表示など）では自動的に同期実行へフォールバックします。これらは1論文あたりの参照数や、極端に多くの論文から引用される文献に上限を設けて処理時間を抑えるため、超大規模では近似になる場合があります。
- 大量取得ではOpenAlex APIへの負荷に配慮してください。

## トラブルシューティング

| 症状 | 対応 |
|---|---|
| 検索で `403` / `401` / レート制限エラーになる | OpenAlex APIキーが未設定・無効・上限超過の可能性があります。2026年2月13日よりAPIキーが必須です。左サイドバー上部の「OpenAlex APIキー」画面でキーを設定し、「接続テスト」で確認してください（→[クイックスタート](#クイックスタート)）。 |
| 検索ボタンを押しても結果が出ない | まず「OpenAlex APIキー」が設定済みか確認してください。次に検索式の構文、年範囲、論文種別、要約あり、英語のみ、最小引用数を確認してください。コマンドライン検索式では各行にTI/AB/TA/TX/FTが必要です。 |
| コマンドライン検索式で検索範囲が選べない | 仕様です。コマンドラインモードでは各行のTI/AB/TA/TX/FT指定が検索範囲になります。標準OpenAlex検索モードでは検索範囲を選べます。 |
| 年別取得にしても10,000件にならない | 年別取得は年ごとの取得上限を広げる機能です。実件数や詳細フィルタにより10,000件未満になります。 |
| Publication Typeが効いているか不安 | 詳細フィルタ内のチップを選択し、検索を再実行してください。複数選択できます。 |
| 同じ著者名が複数出る | Author IDやORCIDが異なる場合は別キーとして扱います。名寄せ診断で同名候補を確認し、同一人物なら統合します。 |
| 別人の同姓同名が混ざる | Author IDが異なる場合は基本的に分離されます。名前のみキーは混入しやすいため、詳細ポップアップで論文・所属・Topicを確認します。 |
| 同じ大学・企業が複数名で出る | 機関名寄せでInstitution ID、ROR、lineage、共同研究先を確認し、必要に応じて統合します。 |
| 親機関寄せしてもまとまらない | 親IDの名称が取得できない場合やlineageが不十分な場合があります。統合マップで任意のグループへ寄せてください。 |
| 名寄せを適用したのに結果が変わらない | 統合したキーが現在の分析対象に含まれているか確認してください。名寄せ後に各分析カードを再描画してください。 |
| 前の分析の名寄せが混ざる | 現在の名寄せをリセットし、必要なJSONだけを明示的に読み込んでください。 |
| 名寄せワークベンチが重い | 表示件数を減らし、同名候補や統合済みに表示を絞ってください。 |
| 技術キーワードに一般語が多い | 追加ストップワードに検索語、一般語、広すぎる分野語を入れて再計算してください。 |
| 技術キーワードが少なすぎる | 最小出現文書数を下げ、抽出対象上限を増やし、追加ストップワードを減らしてください。 |
| 読むべき論文スコアが期待と違う | 目的に応じて重みを調整してください。基礎文献重視なら引用、最近の動向重視ならTopic急増と技術語新規性を上げます。 |
| 系譜図が複雑すぎる | 表示ノード数を減らし、最小関係スコアを上げ、Topicフィルタや年範囲で絞ってください。 |
| 系譜に入っている論文が読むべき論文に出ない | 読むべき論文タブの `技術系譜ノードも含める` をONにしてください。 |
| AIプロンプトが長すぎる | プロンプト投入論文数を減らし、候補論文数も必要に応じて減らしてください。 |
| AIの出力が貼り戻せない | TSVの列名と区切りを確認してください。自由文ではなく、指定列を持つTSVとして出力させます。 |
| Topic分析にAI命名が出ない | Topic命名TSVを貼り戻したうえで、Topic分析のAI反映チェックをONにしてください。 |
| CSV再読込後にAI注釈がない | 保存したCSVに `ai_` カラムが含まれているか確認してください。 |
| グラフが描画されない | データが空、条件に該当するデータがない、またはCDNライブラリを読み込めない可能性があります。 |
| ネットワークが毛玉になる | 最小エッジ重みを上げ、表示ノード数を減らし、年範囲やTopicで絞ってください。 |

## 類似ツールとの違い（Related tools）

OpenAlex を使った書誌計量の優れた OSS は既にいくつもあります。本ツールはそれらを置き換えるものではなく、**「インストールもコードも不要で、ブラウザだけで一通りの分析が完結する」**点で住み分けます。

| ツール | 形態 | ライセンス | 主眼 |
|---|---|---|---|
| **pyalex** | Python ライブラリ | MIT | OpenAlex API ラッパー（要コーディング） |
| **openalexR** | R パッケージ | MIT | R での書誌データ収集（要コーディング） |
| **litstudy** | Python ライブラリ | Apache-2.0 | 文献レビュー＋ネットワーク分析（要コーディング） |
| **bibliometrix / biblioshiny** | R パッケージ＋GUI | MIT/GPL-3 | 多機能な科学計量。GUIだが **R 環境の導入が必要** |
| **VOSviewer** | デスクトップアプリ（Java）/ Web版 | フリーウェア（Web版はMIT） | ネットワーク**可視化**に特化。要インストール |
| **Local Citation Network** | Web アプリ | GPL-3.0 | 引用ネットワークによる**文献探索**に特化 |
| **OpenAlex Explorer** | Web アプリ（Flask/Python サーバ） | MIT | データ探索・可視化。要サーバ起動 |
| **本ツール（OpenALEX Collector）** | **単一HTML（ブラウザ完結・サーバ/インストール不要・ノーコード）** | MIT | 検索→計量分析→**著者/機関の名寄せ**→Topic/資金/ジャーナル分析→ネットワークを一気通貫 |

要点：

- ライブラリ系（pyalex / openalexR / litstudy）は強力ですが、**Python/R を書けることが前提**です。
- GUI 系でも、**bibliometrix は R 環境、VOSviewer は Java の導入**が必要で、Web アプリ系（OpenAlex Explorer 等）は**サーバ起動**を伴うものがあります。
- **本ツールは HTML ファイルを開くだけ**で、検索・分析・名寄せ・可視化・CSV/PNG 出力まで行えます。特に **GUI による著者・機関の名寄せ（disambiguation）** を備える点や、**完全クライアントサイド（データがブラウザ外に出ない）** である点は、上記ツール群にあまり見られない特徴です。

> いずれの類似ツールも、それぞれの目的において優れた OSS です。用途に応じて使い分け・併用してください（例: 可視化を突き詰めるなら VOSviewer、文献探索なら Local Citation Network、スクリプトで自動化するなら pyalex/openalexR）。

## 謝辞・データ提供（OpenAlex / OurResearch）

本ツールは、**OpenAlex** が提供する書誌データなしには成立しません。OpenAlex とその運営母体 **OurResearch** に深く感謝します。

- **OpenAlex** は、論文・著者・機関・掲載先・Topic・引用関係などを網羅する、無料でオープンな学術データのカタログです（2022年公開、Microsoft Academic Graph の事実上の後継）。
- 運営する **OurResearch** は、米国の **501(c)(3) 非営利団体**で、Unpaywall などオープンな学術インフラを開発してきた組織です。
- OpenAlex は **[POSI（Principles of Open Scholarly Infrastructure／オープンな学術インフラの諸原則）](https://openscholarlyinfrastructure.org/)** にコミットし、データ・コード・運営をオープンに保つことを掲げています。本ツールは、その「誰でも使えるオープンな学術インフラ」の上に成り立つ、オープンな一利用例です。

### データのライセンス（CC0）

OpenAlex のデータは **[CC0 1.0（パブリックドメイン相当）](https://creativecommons.org/publicdomain/zero/1.0/)** で公開されています。これにより、本ツールが取得・表示・CSV出力するデータを、利用者が自由に利用・再配布できます。商用の有料書誌データベースと異なり、ライセンス契約や利用許諾なしに使える点が、本プロジェクトの基盤です。

> ただし CC0 はデータそのものへの権利放棄であり、各論文の**本文・全文PDFの著作権は各権利者に帰属**します。全文の取り扱いは各自の利用規約・著作権の範囲内で行ってください。
