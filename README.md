# OpenALEX Collector v6.0

OpenALEX Collector v6.0 は、OpenAlex APIを中心に、学術論文の収集、トピック分析、資金分析、引用分析、共同研究・共著ネットワーク分析、そして著者・機関名寄せをブラウザ上で行うための単一HTMLツールです。サーバーを用意せず、`OpenALEX_Collector.html` をブラウザで開くだけで利用できます。

> すべての論文は、誰かの肩である。

## 概要

**OpenALEX Collector v6.0** は、OpenAlexの論文メタデータを起点に、研究領域の構造を多面的に把握するための分析ツールです。

主に次の問いに答えることを目的にしています。

- その研究領域は伸びているのか。
- どのTopicが増えているのか。
- どの論文、著者、機関、ジャーナルが影響力を持つのか。
- 同姓同名の著者や同名・類似名の機関が、ランキングやネットワークを歪めていないか。
- どの機関どうし、どの著者どうしが共同研究・共著しているのか。
- どの著者がどのTopicを担っているのか。
- どの資金源・助成番号が、どのTopic、機関、著者に関係しているのか。
- どの文献が基礎文献・共通基盤・内部引用ハブになっているのか。

v6.0では、v5.0のコマンドライン検索式、Topic分析、資金分析、引用ネットワーク分析を維持しつつ、**著者・機関名寄せ**を実装しました。著者はOpenAlex Author ID / ORCID、機関はOpenAlex Institution ID / RORを優先して扱い、集計前に名寄せマップを適用します。これにより、同姓同名の著者、表記揺れ、同名異機関、企業グループや親機関単位の集計に対応しやすくなりました。

## v6.0の設計方針

| 方針 | 内容 |
|---|---|
| OpenAlex中心 | 論文母集団形成、Topic、引用文献、機関、著者、資金情報はOpenAlexを主軸にします。 |
| 名寄せを分析基盤に統合 | 取得後のランキング、引用、共同研究、Topic×機関、Topic×著者、資金源×機関、資金源×著者、ネットワーク分析に著者・機関名寄せを適用します。 |
| ID優先・表示名はラベル | 著者名・機関名は表示ラベルとして扱い、集計はAuthor ID、ORCID、Institution ID、ROR、名寄せマップのcanonical keyを優先します。 |
| 分析者判断を尊重 | 自動名寄せを最終判断にせず、ユーザーがGUIで統合・分離できます。 |
| Semantic Scholar不使用 | Semantic Scholarはv6.0では使用しません。大量取得制約を避け、OpenAlex中心で設計しています。 |
| APIキー欄なし | v6.0ではOpenAlex API key入力欄は実装していません。 |
| 登録不要APIのみ | 外部補完はCrossref REST APIとNIH RePORTER APIに限定しています。 |
| 単一HTML | サーバー不要。ブラウザだけで動作します。 |
| 日本語GUI | GUI文言は日本語で統一し、分析意図が分かる説明を各カードに配置しています。 |
| CSV再利用 | 取得済みCSVを再読み込みして分析を継続できます。v6.0では名寄せ用IDカラムもCSVに保存します。 |

## クイックスタート

```bash
# 1. HTMLファイルをブラウザで開く
open OpenALEX_Collector.html

# 2. コマンド行と結合論理式Tを入力
# 例: TA=((sulfide OR oxide OR polymer) near5 electrolyte)

# 3. 必要に応じて所属機関フィルタ、著者フィルタ、年範囲を指定
# 著者・機関は名前だけでなくOpenAlex IDも指定可能

# 4. 「検索を実行」をクリック

# 5. 「著者・機関名寄せ」でGUI名寄せを開く
# 著者または機関を選び、「一覧を更新」→「詳細・統合」で論文・共著者・Topicを確認

# 6. 必要に応じてポップアップ内で「候補をここへ統合」「ここを候補へ統合」「分離」を実行
# ルールは名寄せマップに保存され、各分析に再適用されます

# 7. 各カードの「描画」ボタンで分析し、CSV / PNGをダウンロード
```

対応ブラウザは、Chrome、Edge、Firefox、Safariなどのモダンブラウザです。

## モジュール詳細

### 1. 検索フォーム

OpenAlex APIに対する検索条件を設定します。キーワードを空欄にして、所属機関や著者だけで検索することもできます。

| 入力項目 | 内容 | 例 |
|---|---|---|
| コマンド行 | 1行1条件。各行に`TI=` / `AB=` / `TA=` / `TX=` / `FT=`を明示 | `TI=(solid adj3 electrolyte)` |
| 結合論理式 T | コマンド行を`#01` / `#02`で参照し、AND / OR / NOTで結合 | `T=(#01 AND #02) OR #03` |
| 所属機関フィルタ | セミコロン区切りで複数機関をOR指定。OpenAlex Institution IDも指定可能 | `Meijo University; https://openalex.org/I...` |
| 著者フィルタ | セミコロン区切りで複数著者をAND指定。OpenAlex Author IDも指定可能 | `Akira Yoshino; https://openalex.org/A...` |
| 年範囲 | 開始年・終了年 | `2020`〜`2026` |
| 取得上限 | クエリあたり、または年あたりの取得件数 | `200`, `10000` |
| 年別取得 | 年単位に分けて取得し、10,000件超の領域に対応 | ON/OFF |

詳細フィルタでは、論文種別、ソート順、最小引用数、オープンアクセスのみ、要約ありのみ、英語論文のみを指定できます。コマンドライン検索式モードでは、各コマンド行で検索範囲を明示するため、詳細フィルタの「検索範囲」はグレーアウトされます。

### 2. データテーブル

取得した論文を一覧表示します。

| 機能 | 内容 |
|---|---|
| 表示カラム | タイトル、年、著者、所属機関、ジャーナル、引用数、検索一致、DOI |
| 著者・所属機関表示 | v6.0では名寄せ後の表示ラベルを表示します。元の表示名はCSVの`author_names` / `institution_names`に保持されます。 |
| ソート | 各カラムヘッダをクリックして昇順・降順を切り替え |
| ページネーション | 50件単位で表示 |
| DOIリンク | DOIがある論文は`doi.org`へリンク |
| CSV出力 | v6.0拡張カラムを含む論文CSVを出力 |

### 3. 著者・機関名寄せ

v6.0の中心機能です。OpenAlexから取得した著者・機関エンティティを構造化して保持し、分析前に名寄せを適用します。

#### 名寄せの基本方針

| 対象 | 優先キー | 補助キー | 目的 |
|---|---|---|---|
| 著者 | OpenAlex Author ID | ORCID、正規化名 | 同姓同名の別人を分離し、必要ならGUIで統合する |
| 機関 | OpenAlex Institution ID | ROR、lineage、正規化名 | 表記揺れ・同名異機関・親子機関・企業グループを制御する |

#### GUI名寄せ

v6.0では、キーを直接入力する画面ではなく、GUI上で著者・機関を確認しながら名寄せします。名寄せカードのアイコンは `ID` です。画面上の **名前のみ（IDなし）** は、OpenAlex ID、ORCID、RORが取得できず、名前文字列だけで仮のキーとして扱っているレコードを意味します。

`詳細・統合`ボタンは、著者・機関キーに記号やURL由来の文字が含まれる場合でも安全に動作するよう、クリック属性への受け渡しを修正しています。名寄せ操作は、キーの直接入力ではなく、一覧・詳細ポップアップ・チェック統合から行います。

| 操作 | 内容 |
|---|---|
| 対象選択 | `著者`または`機関`を選択します。 |
| 表示切替 | `すべて（名寄せ後）`、`同じ名前・複数キー候補`、`名前のみ（IDなし）`、`統合済み（結合単位）`で絞り込めます。 |
| 一覧を更新 | 現在のコレクション内に出現する著者・機関を、ID/キー単位で一覧します。 |
| 絞り込み | 名前、OpenAlex ID、ROR、Topic、共著者/共同研究先などで候補を絞り込みます。入力中は短い待ち時間を挟んで再描画するため、大きい集合でも過剰な再計算を避けます。 |
| 並び順 | `名前順（同名を並べる）`、`同名候補を優先`、`論文件数順`、`被引用数順`、`平均被引用順`、`h-index順`を選べます。名前順では同じ著者名・機関名が隣接するため、同姓同名や同名機関の確認が容易です。 |
| 詳細・統合 | 対象キーの論文件数、合計被引用数、平均被引用、h-index、元キー、元表示名、共著者・共同研究先、関連著者/所属機関、Topic、論文Topをポップアップ表示します。 |
| 同じ名前の候補 | 同じ正規化名を持つ別キーを表示します。候補行のボタンから、現在キーを候補へ統合することも、候補を現在キーへ統合することもできます。 |
| チェック統合 | 一覧で複数キーをチェックして、表示順で最初のチェックキーへ残りのキーをまとめます。統合先を明示したい場合は詳細ポップアップで選択します。 |
| 分離 | 選択キーまたは詳細ポップアップ上のキーに対するGUI統合ルールを削除します。ID自体をOpenAlex上で分割するものではありません。 |
| キーコピー | 詳細ポップアップからキーをコピーし、外部メモや名寄せマップの確認に利用できます。 |

GUI名寄せの結果は名寄せマップとしてlocalStorageに保存され、JSONとして出力・読込できます。キーを直接入力する画面はありません。著者ランキング、機関ランキング、引用ランキング、共同研究、Topic×機関、Topic×著者、資金源×機関、資金源×著者、ネットワーク図などの主要分析は、名寄せマップを適用した表示ラベルで再描画されます。

名寄せワークベンチでは、統合後の表示単位に `結合済み Nキー` のバッジを表示し、統合元キーを行内に表示します。`すべて（名寄せ後）` は結合後の単位を一覧し、`統合済み（結合単位）` はGUI統合・表示名変更などの名寄せ処理が入った単位だけを確認するための表示です。

内部的には、著者・機関エンティティの解析結果、名寄せ後プロフィール、表示ラベルマップ、診断結果をキャッシュします。名寄せルールや機関集計単位を変更したときだけ関連キャッシュを無効化し、チェック統合では複数ルールをまとめて保存します。絞り込み入力は短い待ち時間を挟んでから再描画し、統合・分離後は名寄せ一覧と診断を先に更新して、グラフ・Topic・資金・ネットワークなど重い再描画は遅延実行します。これにより、大きめの論文集合でも同じJSON解析とプロフィール集計を何度も繰り返さない設計になっています。

#### 機関集計単位

| モード | 内容 | 主な用途 |
|---|---|---|
| 機関ID単位 | OpenAlex Institution ID / ROR単位で集計 | 通常の機関ランキング、共同研究ネットワーク |
| 親機関寄せ（名称が分かる親だけ） | OpenAlex lineageに基づき、親IDの名称を取得できた場合だけ上位機関へ寄せます。名称不明の親IDには寄せず、元の機関名を維持するため、`親機関 I...` のようなIDだけのノード名は出ません。 | 大学本体・病院・研究所をまとめて見たい場合。ただし親ID名が取得できない場合は個別機関のまま維持されます。 |
| 統合マップ優先 | 名寄せマップで指定した`group:*`等へ統合 | 企業グループ、研究機構、分析者独自分類 |

#### 名寄せ診断

検索またはCSV読込後、以下を確認できます。

| 診断 | 内容 |
|---|---|
| 著者IDカバレッジ | 著者出現のうち、OpenAlex Author IDまたはORCIDを持つ割合 |
| 著者 名前のみ（IDなし） | OpenAlex Author ID・ORCIDがなく、名前だけになっている著者出現数 |
| 同じ名前・複数著者キー候補 | 同じ表示名だが複数キーに分かれている候補 |
| 機関ID/RORカバレッジ | 機関出現のうち、OpenAlex Institution IDまたはRORを持つ割合 |
| RORあり所属 | RORを持つ所属出現数 |
| 同じ名前・複数機関キー候補 | 同じ表示名だが複数キーに分かれている候補 |

#### 名寄せマップ

GUI名寄せや詳細ポップアップでクリック統合します。キーを直接入力して統合ルールを追加する欄はありません。GUIで作成した統合ルールはブラウザ内に保存され、JSONとして出力・読込できます。

詳細ポップアップのクリック処理では、著者・機関キーを安全にエスケープして渡すため、OpenAlex ID、ORCID、ROR、名前由来キーが混在していても `詳細・統合` 操作を安定して実行できます。

名寄せマップはJSONとして保存でき、次回以降の分析に再適用できます。

分離は、名寄せマップに登録された統合ルールを削除する操作です。OpenAlex IDそのものを修正するものではありません。自動的に同じ親キーへ寄った機関を完全に別扱いしたい場合は、機関集計単位を`個別ID`に戻すか、統合マップで分析目的に合うcanonical keyを指定してください。

## Topicスコアの定義

新興Topic候補では、直近3年、直前3年、平均被引用数を用いた簡易スコアを使います。

```text
score = w_recent * recentCount
      + w_delta * max(delta, 0)
      + w_citation * recentAvgCitations
```

| 項目 | 意味 |
|---|---|
| `recentCount` | 直近3年の論文件数 |
| `prevCount` | 直前3年の論文件数 |
| `delta` | `recentCount - prevCount` |
| `recentAvgCitations` | 直近3年論文の平均被引用数 |
| `w_*` | 画面上で調整できる重み |

## ネットワーク指標の定義

| 指標 | 定義 | 解釈 |
|---|---|---|
| 次数 | ノードが接続している相手ノード数 | 共同研究先・共著者の多さ |
| 重み付き次数 | 接続エッジの重み合計 | 共同研究・共著の総量 |
| 媒介中心性 | 最短経路上にどれだけ現れるか | クラスター間をつなぐブローカー性 |
| 論文数 | 該当ノードが関係する論文件数 | 生産量 |
| 平均被引用数 | 該当ノードの論文の平均被引用数 | 影響度・質の目安 |

媒介中心性は、複数の研究コミュニティを橋渡しする著者・機関を見つけるのに有効です。

## 検索構文

### 検索モード

| モード | 内容 |
|---|---|
| コマンドライン検索式 | `#01`、`#02`のような番号付きコマンド行を定義し、最後に`T=(#01 AND #02) OR #03`の形式で結合します。通常のTI/AB/TAキーワード検索はOpenAlex候補を採用し、Collector内部除外は行いません。`nearN` / `adjN`を使った場合だけ、Collector内部で距離判定します。 |
| 標準OpenAlex検索 | 入力した検索語をOpenAlexへ直接渡します。 |

### コマンドライン検索式の基本形

```text
#01  TI=(solid adj3 electrolyte)
#02  AB=((degradation AND capacity) near8 (mechanism OR fade*))
#03  TA=(review)
T=(#01 AND #02) AND NOT #03
```

| 演算子 | 意味 |
|---|---|
| `AND` | 両方を含む |
| `OR` | どちらかを含む |
| `NOT` | 除外 |
| `nearN` | 順不同でN語以内 |
| `adjN` | 左語が右語より前、N語以内 |
| `*` | 任意文字列 |
| `?` | 任意1文字 |

| フィールド | 内容 |
|---|---|
| `TI` | タイトル |
| `AB` | 要旨 |
| `TA` | タイトル＋要旨 |
| `TX` | OpenAlex総合検索対象。候補取得中心 |
| `FT` | OpenAlex fulltext索引。候補取得中心 |

`TI=(solid electrolyte)`、`AB=(solid electrolyte)`、`TA=(solid electrolyte)`、`TA=(solid electrolyte AND interface)`のような通常キーワード・Boolean・ワイルドカード検索では、OpenAlexが返した候補をそのまま採用します。Collector内部で候補を除外するのは、`TI` / `AB` / `TA`内で`nearN` / `adjN`を使い、語間距離の厳密判定が必要な場合だけです。`TX` / `FT`はOpenAlex側の候補取得に使います。Collector内部に本文全文がないため、near/adjの厳密検証とスニペット表示は行いません。

## ユースケース別ガイド

### 同姓同名の著者が多い分野を分析したい

1. 検索を実行します。
2. 「著者・機関名寄せ」で著者IDカバレッジと同じ名前・複数著者キー候補を確認します。
3. 同一人物と判断できる場合は、詳細ポップアップまたはチェック統合で統合します。
4. 著者ランキング、被引用著者、著者ネットワークを再確認します。

### 著者ごとのTopicと資金源の関係を見たい

1. 検索を実行します。
2. 「著者・機関名寄せ」で著者の重複・統合状態を確認します。
3. 必要に応じて同一人物・同一グループを統合します。
4. Topic分析の「著者×Topicマトリクス」と、資金分析の「資金源×著者」「資金源×著者マトリクス」を確認します。

### 企業グループ単位で機関分析したい

1. 通常検索を実行します。
2. 機関集計単位はまず`個別ID`で確認します。
3. 企業本体、中央研究所、子会社などが別キーになっている場合は、詳細ポップアップまたはチェック統合で代表キーへ統合します。任意の`group:*`名が必要な場合だけ、出力した名寄せマップJSONを編集します。
4. 機関ランキング、資金源×機関、Topic×機関、機関ネットワークを確認します。著者単位の関与を見たい場合は、資金源×著者と著者×Topicマトリクスも確認します。

### 大学本体・病院・研究所をまとめて見たい

1. 検索を実行します。
2. 機関集計単位で`親機関寄せ（IDだけのノードを出さない）`を選択します。
3. 名寄せ診断とランキング変化を確認します。
4. 必要に応じて名寄せマップで表示名を調整します。

### 検索式の母集合を確認したい

1. コマンドライン検索式を入力します。
2. 「構文チェック / OpenAlex候補式プレビュー」を実行します。
3. 検索後、データテーブルの検索一致フィールド・演算子・スニペットを確認します。
4. CSV出力して検索式レビュー資料に使います。

## 注意事項

- OpenAlexの著者・機関IDは非常に有用ですが、完全ではありません。著者分裂、誤統合、所属移動、機関階層の扱いは分析者の確認が必要です。
- 名寄せマップは分析目的に依存します。企業グループ単位でまとめるか、研究所単位で分けるかは、調査目的に応じて判断してください。
- 機関集計単位を変更すると、機関ランキング、共同研究、資金源×機関、Topic×機関、機関ネットワークの結果が変わります。著者名寄せを変更すると、著者ランキング、共著ネットワーク、資金源×著者、著者×Topicマトリクスの結果が変わります。
- OpenAlexの`authorships`、`institutions`、`lineage`、`grants`等のカバレッジは分野・出版社・時期により不均一です。
- 引用数はOpenAlex上の被引用数です。分野差、年齢差、出版タイプ差は補正していません。
- h-indexは現在の検索集合内だけで計算されます。研究者・機関の全業績h-indexではありません。
- `TX` / `FT`検索は候補取得中心です。Collector内部で全文を保持しているわけではありません。

## トラブルシューティング

| 症状 | 対応 |
|---|---|
| 同じ著者名が複数出る | 名寄せ診断で同じ名前・複数著者キー候補を確認し、同一人物なら名寄せマップで統合します。 |
| 別人の同姓同名が混ざる | Author IDが異なる場合は基本的に分離されます。表示名が同じ場合は、名寄せワークベンチのキー列・詳細ポップアップで区別します。ネットワーク図のノード名には`[A...]`のようなIDサフィックスを表示しません。 |
| 同じ大学・企業が複数名で出る | GUI名寄せで機関を開き、論文・共同研究先・Topicを確認して統合します。必要に応じて機関集計単位を`親機関寄せ`または`統合マップ優先`に切り替えます。 |
| 親機関寄せしても期待通りまとまらない | 親IDの名称が取得できない場合は、IDだけのノードを避けるため個別機関のまま維持します。詳細ポップアップで元キー・lineage・該当論文を確認し、必要なら統合マップで任意のグループ名へ寄せてください。 |
| 名寄せを適用したのに結果が変わらない | 統合したキーが現在の表示対象と一致しているか確認してください。名寄せワークベンチの`統合済み（結合単位）`で、`結合済み Nキー`バッジと統合元キーが出ているかを確認できます。必要なら名寄せマップをリセットして再統合してください。 |
| 名寄せワークベンチが重い | v6.0では名寄せ用キャッシュと一括保存で軽量化しています。それでも大規模集合で重い場合は、`表示件数`を50件にし、`表示`を`同じ名前・複数キー候補`または`統合済み（結合単位）`に絞り、`並び順`を`名前順（同名を並べる）`にして確認してください。 |
| `hasStrict is not defined` と出る | 古いv6.0修正版を使っている可能性があります。最新版HTMLに差し替えてください。通常の`TI` / `AB` / `TA`検索では内部近傍フィルタを走らせず、`nearN` / `adjN`を含む場合だけ距離判定します。 |
| CSV再読込後に名寄せ情報が不足する | v6.0以前のCSVではID系カラムが無い場合があります。その場合は`name_only（画面上は名前のみ（IDなし））`として扱われます。 |
| グラフが描画されない | データが空、または対象タブの条件に該当するデータが無い可能性があります。 |
| OpenAlex検索で結果が少ない | 年範囲、要約ありのみ、英語のみ、最小引用数、論文種別フィルタを確認してください。 |
| 10,000件を超えそう | 年別取得をONにしてください。 |
